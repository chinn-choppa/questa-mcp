# Разрешённые проекты и DO-сценарии

[English](APPROVED_PROJECTS.en.md)

## Модель доверия

MCP-клиент **не** передаёт команды shell, фрагменты Tcl, пути или параметры vsim. Администратор вручную создаёт локальный JSON-манифест с фиксированными проектами и полным путём к установленному `vsim`. `run_approved_project(project_id)` только выбирает заранее известный идентификатор.

**Важно:** это ограничение API, а не песочница ОС. Даже разрешённый DO-скрипт — исполняемый Tcl с правами пользователя и потенциальными файловыми/сетевыми побочными эффектами. Выполняйте его только в подготовленном **одноразовом** рабочем каталоге и под отдельной ограниченной учётной записью/в изолированной VM. Сервер не гарантирует, что Tcl не обращается за пределы рабочей директории; возможны обращения к включённым через `source` файлам. Не подключайте закрытые RTL или лицензии к неподтверждённому агенту.

## Конфигурация

Задайте переменную окружения `QUESTA_MCP_PROJECTS_CONFIG` с **абсолютным** путём к локальному JSON-файлу, подготовленному оператором. Пример (пути заменяются на действительные абсолютные пути вашей ОС):

```json
{
  "projects": {
    "public-smoke": {
      "workspace": "/absolute/disposable/workspace",
      "executable": "/absolute/questa/bin/vsim",
      "do_script": "run.do",
      "do_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "operator_approved": true,
      "disposable_workspace": true,
      "timeout_seconds": 120,
      "max_output_bytes": 65536,
      "expose_diagnostics": false
    }
  }
}
```

Приведённый хеш фиктивный. Запишите реальный SHA-256 **точно того** `run.do`, который оператор проверил. Путь DO должен быть относительным к рабочему каталогу, существовать, не проходить через символьные ссылки и не содержать `..`. Размер DO — до 128 КиБ, конфигурации — до 64 КиБ; проектов — до 32. Имя бинарника — `vsim` или `vsim.exe`. Изменение сценария блокируется статусом `DO_HASH_MISMATCH`.

## Поведение

- `list_approved_projects()` возвращает только идентификаторы, не пути.
- `run_approved_project(project_id)` вызывает утверждённый `vsim -c -do <разрешённый-файл>` без `shell=True`, собирает вывод в памяти с жёстким лимитом и ограничивает длительность.
- При ошибке запуска/превышении времени/лимите вывода возвращает `TOOL_UNAVAILABLE` / `TIMEOUT` / `OUTPUT_LIMIT`; при коде 0 — `COMPLETED_UNVERIFIED`, **не PASS**.
- `LICENSE_ERROR_EVIDENCE` означает обнаруженный в тексте признак проблемы лицензии, а не реальную лицензионную диагностику в публичном CI.
- Отправка сырых диагностик агенту выключена по умолчанию. `expose_diagnostics=true` разрешает показать первые 20 диагностик, которые могут содержать пути и секреты.
- Статусы компиляции, элаборации и симуляции остаются `UNKNOWN`, пока этап #5 не добавит достоверные доказательства фаз.

Windows/Linux в публичном CI проверяются на имитациях процессов. Работа с реальными Questa/ModelSim, лицензии, различными версиями и завершением дерева процессов на реальных системах: **NOT_RUN**.

## Защита от изменения сценария во время запуска

Сервер читает DO с ограничением размера, сверяет SHA-256 с утверждённым значением и создаёт приватный временный снимок вне рабочего каталога. В `vsim -do` передаётся путь к этому снимку, который удаляется после завершения. Это устраняет окно между проверкой и последующим открытием исходного DO-файла симулятором, **но не гарантирует** изоляцию от злоумышленника с теми же правами ОС, небезопасных `source` или подмены сопутствующих файлов. В Linux чтение конечного файла производится с `O_NOFOLLOW` (при поддержке ОС). Если не удаётся подтвердить остановку дерева процессов, возвращается `TERMINATION_UNCONFIRMED`; **отсутствие процессов не гарантируется**, в частности на Windows. Требуется изоляция ОС и дополнительная приёмка с настоящей Questa.

## Опциональный checker cocotb JUnit

В локальный манифест можно добавить `executable_sha256` и `checker: {"format":"cocotb-junit-v1","expected_tests":["check_counter"]}`. При включённом checker хеш бинарника **обязателен**. Свежий `COCOTB_RESULTS_FILE` ограничен 128 КиБ и 256 тестами. Подтверждённые самопроверки дают `checker_verdict=PASS`, но не полный PASS теста/регрессии. Подмена бинарника до запуска приводит к `EXECUTABLE_HASH_MISMATCH`, после — к `EXECUTABLE_CHANGED`. Подробности: [JUnit evidence](JUNIT_EVIDENCE.md).
