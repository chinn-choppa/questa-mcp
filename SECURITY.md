# Политика безопасности

[English](SECURITY.en.md)

## Сообщение об уязвимости

Не создавайте публичный issue с работающим эксплойтом, токенами или закрытым RTL. Используйте **Report a vulnerability** на вкладке Security репозитория `questa-mcp` после включения GitHub Private Vulnerability Reporting. Если функция пока недоступна — свяжитесь с сопровождающим проекта через приватный канал, не размещая технические детали публично.

## Модель угроз

MCP-клиент может передавать недоверенные параметры. При явно разрешённом профиле сервер может запускать исполняемый файл Siemens с правами пользователя — это чувствительное действие даже для локального stdio.

Текущий прототип:

- по умолчанию не запускает EDA; при явно разрешённом профиле запускает доверенный DO через локальный vsim;
- не принимает произвольные shell/Tcl/DO из MCP-запросов;
- не читает исходные файлы RTL напрямую; проверяет и копирует оператором утверждённый DO-файл;
- принимает ограниченный фрагмент текста для разбора диагностик;
- не открывает сетевых портов и не отправляет телеметрию;
- при поиске бинарника не передаёт абсолютные пути MCP-клиенту.

Перед внедрением запуска процессов обязательны: только доверенные бинарники, отсутствие `shell=True`, строгий root для входных и выходных путей, контроль символьных ссылок, время/память/размер логов, корректное завершение дочерних процессов и явное согласие пользователя на операции с побочными эффектами. MCP-аннотации `readOnlyHint` сами по себе не являются ограничением прав.

## Отдельные среды

Не подключайте внешний MCP к закрытым корпоративным исходникам через неутверждённую облачную модель. Локальный `stdio` не гарантирует, что результаты вызовов не покинут компьютер: это зависит и от самого MCP-клиента, и от модели агента.

## Поддерживаемые версии

До первого стабильного выпуска политика сроков исправления не установлена. Все уязвимости оцениваются индивидуально; список поддерживаемых веток появится вместе с первым релизом.

## Дополнение #2/#3

Парсер не принимает путь к файлу и не открывает локальные журналы: все имена в `text` являются только данными. Вход ограничен 1 МиБ, ответ — 200 записями. Нельзя передавать секретные журналы в облачную модель. Даже заранее разрешённый DO-файл является исполняемым Tcl и должен быть доверенным и вручную одобренным.

## Разрешённые DO-сценарии

Оператор явно подтверждает одноразовый workspace и SHA-256 проверенного сценария. **DO — исполняемый Tcl и может обратиться за пределы workspace.** Сервер не является песочницей ОС; используйте отдельную ограниченную учётную запись/VM. Публикация диагностик в ответе выключена по умолчанию. См. [разрешённые проекты](docs/APPROVED_PROJECTS.md).

## Усиление #4

Проверенный снимок DO в приватной временной директории защищает от изменения оригинала после вычисления SHA-256. Это не защита от изменения файлов, на которые ссылается DO, и не граница полномочий Unix/Windows. Статус `TERMINATION_UNCONFIRMED` требует ручной проверки и очистки среды, а не повторного запуска. Не используйте одноразовый workspace в качестве единственного механизма изоляции.

## Сбор свежих JUnit (экспериментальный)

При включённом checker бинарник закрепляется SHA-256 и проверяется до/после запуска. XML принимается только из нового приватного каталога; символьные ссылки, DTD/ENTITY и несовпадающие счётчики отклоняются. Ошибка UTF-8 или разбора журнала блокирует положительный результат checker. Это **не** криптографическая аттестация производителя и не песочница ОС: доверенный Tcl-сценарий или процесс с теми же правами всё ещё может подменить XML. Содержимое JUnit не выдаётся MCP-клиенту. См. [границу доверия](docs/JUNIT_EVIDENCE.md).

При отмене MCP-запроса очистка теперь обрабатывает повторную отмену и запуск процесса, ещё не завершивший создание, до удаления DO-снимка. Завершение дерева процессов средствами ОС остаётся best-effort и требует отдельной приёмки: гарантированная изоляция и остановка всех потомков не заявляются.

## Метаданные waveform/coverage (#6)

Чтение ограничено заранее разрешёнными относительными файлами, без произвольного пути в MCP-запросе. Содержимое не возвращается; хеширование до 8 МиБ на запись, крупные файлы не хешируются. По умолчанию скрыты абсолютные пути; `expose_artifact_paths` — явное разрешение оператора и возможная утечка инфраструктурных данных в ответе агенту. Символьные ссылки и выход за workspace блокируются по проверкам Python; это **не защита от гонок и злонамеренного процесса с теми же правами ОС**. Wavepeek/wave-mcp и vendor-конвертер не запускаются. См. [угрозы манифеста](docs/ARTIFACT_HANDOFF.md).
