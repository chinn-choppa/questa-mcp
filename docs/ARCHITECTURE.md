# Архитектура

[English](ARCHITECTURE.en.md)

## Роли компонентов

```text
MCP-клиент (Codex / Claude / OpenCode / др.)
           |
      MCP stdio
           |
  questa_mcp.server
     |           |
   runtime    diagnostics
   (поиск)    (разбор логов)
       |      approved
       |      (ручное разрешение)
       |       |
       |    Siemens vsim
```

По умолчанию EDA не запускается. Экспериментальный исполнитель запускает только заранее разрешённые DO-профили через установленный `vsim`; универсального `run_command` нет. Полная изоляция ОС и реальная приёмка продукта пока отсутствуют.

## Почему отдельный репозиторий

- Сервер развивается и выпускается независимо от навыков и установщика `agent-dev-toolkit`.
- `agent-dev-toolkit` впоследствии может устанавливать определённую версию из доверенного реестра; обратной зависимости нет.
- Публичный интерфейс MCP должен работать с любым совместимым клиентом, не только с Codex.
- Повторно используемый код между тремя EDA-адаптерами можно извлекать **после** появления как минимум двух проверенных сценариев.

## Изоляция и воспроизводимость

По умолчанию локальный stdio, без внешнего HTTP и сетевых запросов. Входные и выходные каталоги будущих EDA-операций должны задаваться явно. Каждая операция обязана фиксировать tool/version, конфигурацию сборки, полный exit status, артефакты и статус `NOT_RUN` при пропуске реального выполнения.

## Недопустимые сокращения

Ни `--version`, ни `tools/list`, ни успешная компиляция Python не подтверждают корректность RTL. Обнаруженный бинарник ещё не означает проверенную конфигурацию лицензии. Не объявлять testcase `PASS` только по отсутствию ошибок в текстовом выводе, если не установлен надёжный критерий завершения.

## Предметный сценарий

Существующий проектный DO-скрипт → компиляция → симуляция → assertions/coverage → узкий анализ waveforms.

## Граница доверия и проект исполнения #4

Запрос MCP не должен содержать shell-команды или Tcl/DO. Будущий локальный администратор задаёт разрешённые проекты, доверенные бинарники, существующие DO-файлы, корни рабочих пространств и лимиты. Агент может выбирать только непрозрачный идентификатор из списка. Канонические пути и символьные ссылки проверяются до запуска. Даже разрешённый DO-сценарий обладает полномочиями пользователя: он требует отдельной проверки и явного включения. Сейчас такого исполнителя **нет**.

Результат парсера `FAIL` доказывает только обнаруженный признак ошибки; `UNKNOWN` не означает успех. Статусы компиляции, элаборации, симуляции и assertions будут отделены в #5.

Разные версии Questa могут использовать QIS/Qrun (новый маршрут) или vlog/vopt/vsim (совместимый). Будущий адаптер должен выбирать проверенный профиль по редакции и версии, не переключать его неявно.

Реализован экспериментальный исполнитель по явному списку, см. [разрешённые проекты](APPROVED_PROJECTS.md). Это не песочница ОС и не подтверждённый профиль конкретной Questa.
