# Совместимость

[English](COMPATIBILITY.en.md)

| Уровень | Ожидается | Подтверждено на момент создания |
| --- | --- | --- |
| Python | 3.11+ | Реальные unit/MCP тесты на 3.11/3.13 Windows/Linux |
| MCP | SDK 2.3.0, stdio | Реальные `tools/list`/`tools/call` в CI |
| Windows | Планируется | EDA `NOT_RUN` |
| Linux | Планируется | EDA `NOT_RUN` |
| Siemens Questa / ModelSim | Разные версии, после исследования | `NOT_RUN` |
| Корпоративные проекты | Только в разрешённой среде | Не использовались |

Прототип не устанавливает EDA-бинарник и не проверяет его лицензию. Пользовательские версии инструмента выбираются явно через `QUESTA_MCP_EXECUTABLE` или стандартный `PATH` только для безопасного обнаружения. Экспериментальный запуск уже требует ручного разрешения и отдельного одноразового workspace; реальный запуск лицензируемого EDA остаётся `NOT_RUN`.

Questa/ModelSim — коммерческие инструменты. Запуск может потребовать лицензии; сервер не поставляет симулятор, модель лицензирования и конфиденциальные RTL-исходники.

## Измерено в CI 2026-11-05

Подтверждены только Python 3.11/3.13, MCP SDK 2.3.0 и протокол `tools/list`/`tools/call` через `stdio` на `ubuntu-latest` и `windows-latest`: [журнал](https://github.com/chinn-choppa/questa-mcp/actions/runs/42054703978). Любая реальная Questa/ModelSim, лицензия, поддержка разных редакций и Python 3.15 — **NOT_RUN**. Это уточнение имеет приоритет над исходной таблицей bootstrap.

Для Questa 2025.2+ cocotb документирует отдельный маршрут QIS/Qrun и прежний совместимый маршрут vlog/vopt/vsim. Это **не** подтверждение поддержки Qrun данным сервером: сначала нужны реальные проверки конкретной версии/редакции. См. [документацию cocotb](https://docs.cocotb.org/en/stable/simulator_support.html).

Опциональный запуск DO проверен только с mock-процессами. Командная совместимость и уничтожение деревьев реального Siemens vsim не подтверждены.

Опциональный сборщик cocotb JUnit использует предусмотренную cocotb переменную `COCOTB_RESULTS_FILE`. Реальные DO-сценарии и конкретные редакции Siemens остаются **NOT_RUN**. Закрепление SHA-256 бинарника проверяет утверждённый локальный файл, **не** подлинность Siemens, лицензию и не изоляцию ОС. Успех независимых SVA/coverage из JUnit не выводится. См. [сборщик](JUNIT_EVIDENCE.md).

## Совместимость внешних анализаторов (#6)

Маршруты VCD/FST основаны на документированных возможностях Wavepeek и Tencent wave-mcp, **не на фактически выполненном вызове**. Нативный WLF не считается поддерживаемым напрямую; `wlf2vcd` описан только для отдельных старых ModelSim и не запускается сервером. UCDB обрабатывается только средствами производителя. Windows/Linux CI проверяет metadata-слой, не совместимость установленных внешних анализаторов. См. [манифест](ARTIFACT_HANDOFF.md).

Пофазный запуск через `vsim -c -do` является экспериментальным и проверен только на mock-процессах; не подтверждает доступность отдельных команд vlog/vcom в конкретных Siemens/ModelSim. Смысл фаз определяется доверенными DO. Фактическое применение `QUESTA_MCP_SEED` симулятором не проверено. См. [контракт](PHASE_RUNNER.md).

Каталоги run_id проверяются только на синтетических процессах Windows/Linux. Коммерческий DO должен сам читать `QUESTA_MCP_ARTIFACT_DIR`. Реальные Siemens и внешние VCD/FST/UCDB анализаторы — `NOT_RUN`. См. [режим](RUN_ARTIFACTS.md).
