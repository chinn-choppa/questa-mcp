# Достоверность результатов верификации (M3 / #5)

[English](VERIFICATION.en.md)

Успех процесса и результат самопроверяющегося теста — **разные факты**. Отдельно отслеживаются `compile`, `elaboration`, `simulation` и `checker`. Код возврата 0 и строка «TEST PASSED» **не доказывают** прохождение теста.

## Контракт данных

Внутренняя модель `questa_mcp.verification` принимает `test_id`, необязательный `seed` (0…2³²−1), `tool` (`questa`/`modelsim`), `tool_version`, `os`, `artifacts` (имя → SHA-256), `phases.compile|elaboration|simulation` и `checker`.

У процесса есть признаки `started`, `completed`, `exit_code`, `timed_out`, `cancelled`, `log` и необязательный `tool` (`vlog`/`vcom`/`vsim`). Статусы: `NOT_RUN`, `UNKNOWN`, `COMPLETED`, `FAILED`, `TIMEOUT`, `CANCELLED`. `COMPLETED` — только завершение заявленного процесса, а не PASS. Ошибки сохраняют исходную строку журнала и номер этой строки. Для ошибки по ненулевому коду отдельным свидетельством является код процесса.

`checker`: `executed`, `completed`, `checks_run`, `failures`, `success_evidence={source_line,raw}`, `failure_evidence`. Пустое число проверок и отсутствие положительного свидетельства не подтверждают успех; произвольная строка `raw` сама по себе не доказывает подлинность выполнения.

## Граница доверия

MCP-инструменты `assess_verification_run(record)` и `assess_regression(runs)` получают данные **от клиента**. Поэтому положительный результат остаётся `UNKNOWN` с `CALLER_SUPPLIED_UNVERIFIED` даже при всех exit code 0 и положительном маркере checker. Ошибки/fatal — отрицательные признаки (`FAIL`) с исходными строками, но также не доказывают запуск коммерческого EDA.

Параметр внутреннего Python API `attested=True` проверяет переход к `PASS` **только на синтетических фикстурах**, недоступен MCP. Настоящий PASS потребует будущего доверенного сборщика результатов локального запуска и проверяемого происхождения артефактов. Текущий исполнитель DO (#4) по-прежнему не подтверждает прохождение отдельных фаз.

## Регрессия

До 32 записей, уникальные пары (`test_id`, `seed`), сохранение причин/свидетельств и подсчёт `PASS/FAIL/UNKNOWN/NOT_RUN`. Отрицательный признак → `FAIL`; вся регрессия `PASS` только если **все** записи подтверждены доверенным коллектором и самопроверками. Иначе `UNKNOWN` или `NOT_RUN`.

Размер запроса до 1 МиБ. Имена, SHA-256 и версии из запроса являются заявлениями клиента, **не проверенными локальными файлами**. Не передавайте закрытые журналы и ключи.
