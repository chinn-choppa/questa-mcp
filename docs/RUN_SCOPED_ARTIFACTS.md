# Артефакты, привязанные к конкретному запуску (#6)

[English](RUN_SCOPED_ARTIFACTS.en.md)

## Назначение и граница доверия

В отличие от `list_approved_artifacts(project_id)`, который читает существующие файлы рабочей директории **без подтверждения происхождения**, экспериментальный сборщик запуска создаёт **новый пустой каталог** для одного вызова `run_approved_project(project_id)`.

При включении настройки оператором сервер передаёт путь к нему в окружении симулятора через `QUESTA_MCP_ARTIFACT_DIR`. Утверждённый DO-сценарий может записать туда заранее перечисленные VCD/FST/WLF/UCDB-файлы. MCP анализирует **только их метаданные** после завершения процесса. Он не запускает Wavepeek, wave-mcp, Tcl от агента и конвертер WLF.

## Конфигурация

В дополнение к уже обязательным полям утверждённого проекта задайте следующие:

```json
{
  "capture_run_artifacts": true,
  "executable_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "artifacts": [
    {
      "id": "wave",
      "path": "waves/tb.vcd",
      "format": "vcd",
      "declared_time_unit": "ns"
    }
  ],
  "expose_artifact_paths": false
}
```

Значение SHA-256 здесь только пример. Для включения режима **обязательны** заранее проверенный SHA-256 бинарника и хотя бы одна корректная запись `artifacts`. Сохраняются лимит 8 записей, запрет обхода путей/символьных ссылок и ограничение хеширования до 8 МиБ на файл.

Утверждённый DO может построить относительное имя файла из переданной переменной:

```tcl
set artifact_file [file join $::env(QUESTA_MCP_ARTIFACT_DIR) waves tb.vcd]
file mkdir [file dirname $artifact_file]
# Далее используйте документированную команду экспорта вашей редакции Questa.
```

Это только фрагмент уже проверенного оператором DO-сценария, а **не** вход MCP. Для него нужно обновить утверждённый `do_sha256`. Команда экспорта зависит от редакции и должна проверяться на реальном Siemens отдельно.

## Хранение и передача

**По умолчанию** каталог временный: при возврате из инструмента удаляется, остаются только хеши и сведения о файлах. Это безопаснее для публичного прототипа, но такой путь **невозможно затем открыть во внешнем анализаторе**.

Для последующего локального открытия артефактов оператор может дополнительно указать `run_artifact_store` — **существующий абсолютный каталог вне `workspace`**, предназначенный для результатов. Сервер создаёт под ним новый уникальный подкаталог на каждый вызов и **не удаляет его автоматически**. Только при одновременном `expose_artifact_paths=true` в ответе появятся локальные пути, которые разрешённый агент сможет передать Wavepeek или wave-mcp. Оператор отвечает за лимиты дискового пространства, сроки хранения и ручную очистку; этот MCP **не устанавливает дисковую квоту**. Не сохраняйте закрытые волны в общедоступном каталоге.

## Достоверность

Ответ `run_approved_project` включает `run_provenance.run_id` и `run_artifacts` со сведениями `run_id`, `retained`, `capture_mode`, `observed_count` и `items`.

- Если завершённый процесс оставил разрешённый файл в свежем каталоге, у него `origin=FRESH_RUN_DIRECTORY_OBSERVED` и `observed_under_run_id=<run_id>`.
- **`produced_by_run_id=null` и `production_verified=false` сохраняются всегда.** Файл мог создать любой код Tcl, обладающий правами пользователя, поэтому наблюдение внутри нового каталога не равно криптографическому доказательству происхождения.
- При отсутствии файла, незавершённом процессе, timeout, превышении лимита вывода или изменении SHA-256 бинарника `observed_under_run_id=null`. Текстовые пути из старого workspace не повышаются до свежих.
- `format_validated=false`, `external_execution=NOT_RUN`, статусы независимых SVA и общий `test_verdict` остаются такими же консервативными, как раньше. SHA-256 и VCD-расширение не удостоверяют формат, полноту проверки либо существование лицензии.

Ни удаление временного каталога, ни запись в операторский `run_artifact_store` не предоставляют изоляции ОС. Запуск доверенного Tcl должен выполняться под ограничённой учётной записью/в VM; процесс с теми же правами может вмешиваться в записи. При отмене или ошибке в сохраняемом каталоге могут остаться неполные файлы — не используйте их как свидетельства успешной верификации.

## Подтверждённое тестирование

Публичные тесты имитируют процессы `vsim`, показывают различие старых и свежих файлов, отдельные случайные идентификаторы запусков, отсутствие утечек путей без разрешения, сохранение по opt-in, запреты неправильного пути и работы без SHA-256, обработку повреждения бинарника/timeout и **реальный MCP `tools/call` с mock-процессом**. В отдельном Linux CI **настоящий Wavepeek 3.2.0** открыл публичные VCD и FST, полученные из результатов mock-разрешённого процесса. FST создан открытым GTKWave `vcd2fst`; оба сигнала корректно изменились между 0 и 5 нс. [GitHub Actions](https://github.com/chinn-choppa/questa-mcp/actions/runs/42195636610): `WAVEPEEK_PUBLIC_VCD=PASS`, `WAVEPEEK_PUBLIC_FST=PASS`. **Лицензируемая Siemens Questa, wave-mcp, WLF/UCDB и независимые RTL assertions: NOT_RUN.**
