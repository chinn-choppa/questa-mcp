# Артефакты, привязанные к каталогу запуска (#6)

[English](RUN_ARTIFACTS.en.md)

Старый инструмент `list_approved_artifacts(project_id)` остаётся строго read-only и рассматривает существующие файлы рабочего каталога как **неаттестованные**. Новый режим позволяет оператору подготовить *отдельный новый каталог для каждого seed* и сохранить в нём выходные файлы симуляции, не создавая видимость подтверждённого происхождения данных.

## Разрешённая конфигурация

Дополните профиль с `phase_scripts` и `regression_seeds`:

```json
{
  "run_artifacts_dir": "run-results",
  "run_artifacts": [
    {"id": "trace", "path": "wave.vcd", "format": "vcd", "declared_time_unit": "ns"},
    {"id": "coverage", "path": "coverage.ucdb", "format": "ucdb"}
  ],
  "expose_artifact_paths": false
}
```

Каталог `run-results` должен заранее существовать внутри разрешённого `workspace`, не быть символьной ссылкой или junction. Путь строго относителен, без переходов `..`, обратных слешей, двоеточий, NUL и абсолютных путей. Список артефактов непустой, до 8 записей с форматами VCD/FST/WLF/UCDB.

При каждом seed `run_approved_regression` создаёт отдельный непредсказуемый каталог `run-results/<run_id>` с ограниченными правами при поддержке ОС и передаёт **фиксированную** переменную окружения `QUESTA_MCP_ARTIFACT_DIR` всем трём утверждённым процессам. Разрешённый DO должен явно прочитать эту переменную и записать туда файлы. Имена файлов заранее согласованы оператором, агент не выбирает ни путь, ни произвольный DO.

## MCP-инструменты и результаты

Результат `run_approved_regression` содержит `runs[].run_id`, `runs[].artifact_manifest` и `runs[].artifact_origin`. Отдельный read-only инструмент `list_run_artifacts(project_id, run_id)` позволяет повторно прочитать только заранее разрешённые файлы указанного каталога. `run_id` — 24 символа lowercase hex, не путь.

Успешное чтение файла возвращает `state=HASHED` (для файлов до 8 МиБ), размер, SHA-256, формат из конфигурации и возможные внешние маршруты. Для большого файла хеш пропускается. `format_validated=false`, `external_execution=NOT_RUN`, `produced_by_run_id=null` остаются неизменными. Новые поля:

- `observed_in_run_id` — идентификатор **каталога**, в котором обнаружен файл.
- `origin=OBSERVED_IN_RUN_DIRECTORY_NOT_VENDOR_ATTESTED` — факт нахождения в каталоге конкретного запуска, **не доказательство производства Siemens**.

Файл сохраняется после завершения и доступен локальному анализатору при `expose_artifact_paths=true`, если оператор явно разрешил выдавать абсолютный путь. Автоматических запросов к Wavepeek/wave-mcp, конвертации WLF и сетевых отправок нет.

## Безопасность и хранение

Сервер **не удаляет** сохранённые каталоги автоматически: оператор отвечает за права на `run-results`, квоты диска, сроки хранения и удаление. Технический лимит чтения/хеширования 8 МиБ **не ограничивает размер записываемого симулятором файла**. Подмена файла другим процессом с теми же правами ОС не исключена. Каталог с random run_id снижает случайное смешение результатов, но не является песочницей или криптографической аттестацией.

При некорректном/недоступном каталоге запуск отклоняется, а не продолжается с ложным свидетельством. Публичные тесты моделируют новый каталог, два seed, недоступные/запрещённые пути, скрытие/раскрытие путей и настоящий MCP tools/call. Реальная Questa, `wave-mcp`, wlf2vcd, WLF/UCDB и аттестация производителя: **NOT_RUN**. Реальный Wavepeek VCD/FST отдельно проверен в Linux CI на mock-EDA.

## Передача разрешённого файла внешнему анализатору

`prepare_run_handoff(project_id, run_id, artifact_id, consumer)` возвращает *локальный указатель*, а не вызывает анализатор. `consumer` строго `wavepeek` или `wave-mcp`. Оператор обязан включить `expose_artifact_paths=true`, иначе ответ `OPT_IN_REQUIRED` без пути. Только разрешённые VCD/FST-файлы в статусе `HASHED` или `HASH_SKIPPED_LARGE_FILE` получают `status=READY_FOR_EXTERNAL_CLIENT`. WLF/UCDB получают `UNSUPPORTED_NATIVE_FORMAT`, отсутствующие файлы — `ARTIFACT_UNAVAILABLE`. Ответ включает путь, формат, размер, доступный SHA-256, `format_validated=false`, `vendor_attested=false`, `external_execution=NOT_RUN`. Доверенный внешний клиент самостоятельно открывает файл. Эта операция **не подтверждает**, что Wavepeek/wave-mcp действительно прочитали файл или что сигнал корректен.

## Проверка реального внешнего Wavepeek (2026-11-06)

[GitHub Actions](https://github.com/chinn-choppa/questa-mcp/actions/runs/42196936606): официальный Wavepeek v3.2.0 загружен с проверкой SHA-256 и прочитал `tb.clk` из разрешённых VCD и FST. Путь получен **через настоящий MCP** `run_approved_regression` → `prepare_run_handoff`; DO-фазы заменены mock-процессами. FST получен открытым `vcd2fst` (GTKWave) исключительно в CI. Два результата: `WAVEPEEK_PUBLIC_VCD=PASS`, `WAVEPEEK_PUBLIC_FST=PASS`. Это свидетельствует о работоспособности **передачи файлов**, но не подтверждает реальную Questa, авторство Siemens или общий PASS RTL. `wave-mcp`, WLF/UCDB и лицензируемый EDA — **NOT_RUN**.

Исправление безопасности: отсутствующие файлы и незавершённые фазы не получают `observed_in_run_id`. Переменные `QUESTA_MCP_SEED`, `COCOTB_RESULTS_FILE` и `QUESTA_MCP_ARTIFACT_DIR` очищаются от унаследованных значений перед заполнением доверенными значениями текущего запуска.
