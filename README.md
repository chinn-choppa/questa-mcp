# questa-mcp

[English](README.en.md) · [Участие в разработке](CONTRIBUTING.md) · [Безопасность](SECURITY.md)

Локальный MCP-сервер для детерминированного запуска регрессий и анализа симуляций Questa/ModelSim.

> **Статус: bootstrap / экспериментальный (0.0.1).** Проект содержит проверяемый каркас MCP, безвредное обнаружение установленного инструмента и структурированный разбор текстовых диагностик. Без явной настройки он **не запускает** компиляцию или симуляцию и не может подтверждать работоспособность коммерческих инструментов. См. [план](docs/ROADMAP.md).

## Для чего нужен

Поддержка существующих DO/Tcl-сценариев, машинно-читаемых результатов и работы с осциллограммами.

**Принципы:** отдельно от `agent-dev-toolkit`; свободная установка из исходников; никаких встроенных EDA-бинарников, лицензий, облачных запросов и непрошеных изменений файлов проекта. Каждая команда имеет ограниченную область доступа и возвращает наблюдаемые доказательства, а не догадки.

## Быстрый старт

Нужен Python 3.11+ и установленный `uv`. Для самого MCP-сервера нужен совместимый MCP SDK v2.3.0; SDK будет установлен в локальное виртуальное окружение при выполнении `uv sync`.

```bash
git clone https://github.com/chinn-choppa/questa-mcp.git
cd questa-mcp
uv sync
uv run questa-mcp
```

Локальная конфигурация клиента MCP (пример структуры; конкретный путь к `uv`/проекту и формат конфигурации зависят от клиента):

```json
{
  "mcpServers": {
    "questa-mcp": {
      "command": "uv",
      "args": ["--directory", "/absolute/path/to/questa-mcp", "run", "questa-mcp"]
    }
  }
}
```

Это пример для клиентов с ключом `mcpServers`; Codex и OpenCode используют собственные схемы. Все пути должны указывать на доверенную локальную копию.

## Доступные инструменты прототипа

| Tool | Назначение | Граница |
| --- | --- | --- |
| `server_info` | Идентификатор сервера, состояние, ограничения | Только чтение |
| `tool_status` | Поиск установленного `vsim` или пути из переменной `QUESTA_MCP_EXECUTABLE` | Не запускает EDA-продукт |
| `parse_diagnostics` | Разбор `vsim`/`vlog`/`vcom` и UVM с исходными строками | До 1 МиБ и 200 записей |

Экспериментальный исполнитель требует явного разрешения оператора: лицензируемая симуляция и интерпретация coverage будут добавлены после безопасной приёмки.

## Воспроизводимые проверки

```bash
python -m unittest discover -s tests -v
python -m compileall -q src tests
```

CI выполняет реальные `tools/list` и `tools/call` через `stdio` на Windows/Linux с Python 3.11/3.13 и MCP SDK 2.3.0. Реальный EDA остаётся `NOT_RUN`. Python 3.15 — `NOT_RUN`.\n\nПосле `uv sync` проверьте запуск `uv run questa-mcp` с MCP Inspector или настоящим MCP-клиентом. Одна лишь установка или `tools/list` **не доказывает** успешное выполнение EDA-команды. До появления соответствующих реализаций состояние таких проверок — `NOT_RUN`.

Questa/ModelSim — коммерческие инструменты. Запуск может потребовать лицензии; сервер не поставляет симулятор, модель лицензирования и конфиденциальные RTL-исходники.

## Экспериментальный запуск разрешённых проектов (#4)

Оператор может явно включить инструменты `list_approved_projects` и `run_approved_project(project_id)` через локальный манифест. DO-файл предварительно копируется в приватный временный снимок после проверки SHA-256. Запускается только заранее согласованный DO-файл с проверкой SHA-256; произвольные Tcl и пути от MCP запрещены. Подробнее о модели доверия и ограничениях в документе о [разрешённом запуске](docs/APPROVED_PROJECTS.md). Реальная лицензируемая Questa: **NOT_RUN**. Даже нулевой exit code возвращается как `COMPLETED_UNVERIFIED`, а не PASS.

## Фазовая модель верификации (#5)

Инструменты `assess_verification_run(record)` и `assess_regression(runs)` разделяют компиляцию, элаборацию, симуляцию, проверки и регрессии. Положительные заявления клиента **не повышаются до PASS**. См. [контракт верификации](docs/VERIFICATION.md). Реальный Siemens EDA: **NOT_RUN**.

## Экспериментальные самопроверки cocotb (#5)

Утверждённый локальный DO-профиль может включать `checker.format="cocotb-junit-v1"`, точный список `expected_tests` и SHA-256 бинарника `executable_sha256`. Для каждого выполнения назначается новый `COCOTB_RESULTS_FILE`. При нулевом коде процесса и полном отчёте по всем ожидаемым тестам возвращается `checker_verdict=PASS` **только для самопроверок cocotb**. Общий `test_verdict`, внешние assertions и регрессия остаются `UNKNOWN`, если нет отрицательного свидетельства для `FAIL`. Настоящая лицензируемая Questa не запускалась. См. [интеграцию JUnit](docs/JUNIT_EVIDENCE.md).
